## 1. Резюме (TL;DR)

**Главный вывод: не переписывать продукт.** Ванильный JS, 0 зависимостей, работа с `file://` — это не MVP-облик, это и есть ваш moat. В корпоративном сегменте РФ (банки, госсектор, телеком, ИТ-компании с внутренними регламентами) «один HTML-файл, который не звонит наружу» продаётся лучше, чем SaaS. React/Next-рерайт здесь — потеря продукта.

**Позиционирование:** RabbitMQ Designer — мост между архитектурной схемой и реальным брокером. Сегодня конкуренты разделены на две несвязанные группы:

| Группа | Игроки | Чего не умеют |
|---|---|---|
| **Диаграммы** | tryrabbitmq.com, jmcle/rabbitmq-visualizer, plexsystems/rabbit-viz (архив) | Рисуют, но не дают артефактов: ни кода, ни конфига, ни документа |
| **Живые инспекторы** | RabbitGUI (500+ devs), Ticketman, Confible | Требуют доступа к брокеру → не работают в закрытом контуре, не годятся для проектирования и нормоконтроля |
| **Конвертеры definitions → DOT** | rabbitmq-graphviz (46★), sldblog/rabbitmq-graph | Только статичная картинка |

**Свободная ниша:** design-time инструмент, который из одной схемы даёт **definitions.json + код + документ для нормоконтроля**, работает офлайн и в air-gap. Это и есть ваш рынок.

**Целевая аудитория (по приоритету):**
1. Java-разработчики в российских средних/крупных компаниях — нужна Spring AMQP-конфигурация и документ для нормоконтроля.
2. Архитекторы / техлиды — нужен diff топологий, ADR, диаграммы.
3. Junior/студенты — интерактивное обучение маршрутизации (ваш главный маркетинговый актив).

**Стек (коротко):** Vanilla JS + esbuild (сборка в один файл) + Vitest/Playwright + GitHub Actions + Astro (сайт/доки) + Cloudflare Pages/GitHub Pages + ЮKassa + **BYOK-архитектура для AI** (GigaChat/YandexGPT/локальный Ollama).

**Бюджет:** ~3–6 тыс ₽/мес, из них 60–80% — ваша подписка на AI-инструменты разработки. Инфраструктура — 0 ₽.

**Ближайшая цель на 3 месяца:** не «выход на рынок», а **доказательство спроса** — 500+ целевых визитов, 3 публикации на Хабре, 50+ звёзд, первые донаты/оплаты Pro.

### 2.2 Блокеры выхода на рынок (найдено в коде)

| # | Проблема | Влияние | Решение |
|---|---|---|---|
| B1 | **Загружает JSZip с `cdnjs.cloudflare.com`** | В РФ и в закрытом контуре cdnjs **регулярно заблокирован** → «офлайн-0-зависимостей» не выполняется. Плюс supply-chain риск | Убрать CDN: писать ZIP на нативном `CompressionStream('deflate-raw')` + свой ZIP-writer (~120 строк). Получаете честный air-gap |
| B2 | **Нет `localStorage` / автосохранения** | Топология теряется при перезагрузке. Для инструмента под нормоконтроль это критично | Автосейв в localStorage + «Недавние», импорт/экспорт `.rmq.json`, отметка «изменено» |
| B3 | **Нет `package.json`, нет тест-раннера, нет CI** | `test-logic.js` и `test-rk.js` headless и **уже работают**, но запускаются руками через `node test-logic.js`. Никто их не запускает на PR → регрессы ловятся только вручную | `package.json` + Vitest + GitHub Actions |
| B4 | **Нет файла `LICENSE`** | README обещает MIT, но файла нет. Юридический риск: enterprise-клиент попросит — придётся доказывать | Добавить `LICENSE` (MIT) + `NOTICE` |
| B5 | **Нет SEO-метаданных**: description, OG, canonical, JSON-LD, favicon, sitemap | GitHub Pages-страница не индексируется как продукт. Трафик из поиска = 0 | Мета-теги + JSON-LD `SoftwareApplication` + OG-изображение |
| B6 | **Описание репозитория = «Песочница»**, нет тем, нет social-preview, имя `MQ-Designer.github.io` | Репозиторий выглядит как черновик. 0 звёзд при 46★ у `rabbitmq-graphviz` — из-за этого же | Переименовать в `rabbitmq-designer`, description, topics, PNG-превью, шаблоны Issues |
| B7 | **Мусор в репозитории**: `chrome.log`, `chrome2.log`, `server.log`, `gen-out.txt` (31 КБ), `gen-help.js`, `test.md`, `rk-report.md`, `uitest.html`, `doc-preview-*.md`, `smoke*.js` | `.gitignore` их перечисляет, но они **уже закоммичены** (gitignore не раз unemit'ит). Всё это видно на GitHub | `git rm --cached` + перенести тесты в `tests/` |
| B8 | **Одна архитектура экспорта — Java** | Java-бекенд — 30–40% рынка RU, но TypeScript/Python/Go — ещё 40% | Добавить экспорт в TS/Python/Go (через AI-агента — см. §5.1) |
| B9 | **Нет сайта**: страница = приложение | Нет лендинга для SEO/конверсии, нет блога, нет доков | Astro: лендинг + доки + блог в одном репозитории |
| B10 | **Нет каналов обратной связи и метрик** | Непонятно, что делают пользователи и чего хотят | GitHub Discussions + pre-filled issues + Яндекс.Метрика |

### 2.3 Технический долг

- `render.js` — 96 КБ в одном файле, смешивает SVG-рендер, инспектор, тосты, RAF-цикл. Рефакторить **после** того, как появятся тесты в CI (иначе регрессии не отловить).
- Глобальное пространство имён (`window.RMQ`, `window.I18N`) — работает, но не масштабируется. Лечится esbuild-бандлингом в IIFE, а не рефакторингом «на вкус».
- Нет типов. `core.js` — чистая логика, идеально кандидат на JSDoc + `checkJs` (без миграции).

```

│  index.html (дистрибутив)          ← один файл, air-gap   │

│         ├── exporters   — definitions.json / код / docs   │
│         ├── exporters2  — terraform / compose / mermaid  │
│         ├── linter      — правила качества топологии     │
│         ├── ai          — BYOK + локальный OpenAI API     │
│         └── i18n / help / presets                        │

              ▲
┌─ site/ ───┴──────────────────────────────────────────────┐
```

### 4.2 Почему НЕ переписывать на React/Vue

| Аргумент «за» React | Почему он не работает здесь |
|---|---|
| «Так удобнее развивать» | `render.js` — 96 КБ, но он работает и покрыт headless-тестами. Переезд = 3–4 недели на соло без выручки |
| «Нужен компонентный подход» | Инспектор и канвас — это 5–7 связанных сущностей. React даст здесь больше ceremony, чем пользы |
| «Нужны npm-зависимости» | 1 зависимость = 1 точка отказа в air-gap и в аудите ИБ. В корпоративном продакшене «0 зависимостей» — аргумент в сделке |
| «Так можно делать SPA с роутингом» | SPA-роутинг → `type="module"` → **ломается `file://`** (CORS). Ваша фишка «открыл index.html — работает» технически несовместима с нативными ES-модулями |
| «Marketplace-расширения» | VS Code Extension пишется на TypeScript, а не на React. Расширение может открывать/генерировать ваш HTML |

**Компромисс (если захочется TS):** не мигрировать код, а **переписать только новые модули** (`exporters2.js`, `linter.js`, `ai.js`) на TypeScript, собирать esbuild'ом. Старый код оставить как есть. Если появится YAML-DSL — тогда перевести `core.js` на TS, там типы действительно дают пользу.

### 4.4 Сборка: как именно

```js
// build.mjs — esbuild, ~25 строк
import { build } from 'esbuild';
import { readFileSync, writeFileSync, mkdirSync } from 'node:fs';

// 1. Бандлим весь JS в IIFE (НЕ ESM — иначе сломается file://)
await build({
  entryPoints: ['src/app.js'],
  bundle: true,
  format: 'iife',
  minify: true,
  target: 'es2020',
  outfile: 'dist/app.js',
});

// 2. Инлайним CSS + JS + весь контент в один HTML
//    → dist/index.html = единый файл, который скачивают и открывают
```

Результат: `dist/index.html` — **единственный** артефакт. Релиз тянет его в `Releases` как `rabbitmq-designer-<version>.html` + `.zip`.

**Побочная выгода:** исчезает проблема «какие файлы надо скачать» и «забыл прислать help-content.js». Для enterprise-клиента это отдельная ценность: «присылаю один файл, он работает у нас в закрытом контуре».

## 5. AI-контур

Три независимых слоя. Не смешивать.

### 5.1 Слой 1: AI как инструмент разработки (ваша главная выгода)

Вы соло-разработчик, выходит на рынок — AI здесь даёт максимальный множитель скорости.

| Инструмент | Для чего конкретно в этом проекте |
|---|---|
| **Cursor** (или **OpenCode** / **Claude Code** как CLI-агент) | Рефакторинг `render.js` на модули; миграция `test-logic.js`/`test-rk.js` в Vitest-спеки; написание экспортеров |
| **GitHub Copilot** | Быстрые правки, completions, комментарии к PR |
| **AI-агент в CI** | Ревью PR >500 строк перед мержем (экономия: гонять только на больших PR) |

**Правила, которые экономят деньги и нервы:**

1. **Golden files.** Для каждого пресета и каждой фичи — эталонный `definitions.json` + эталонный Java-файл в `tests/golden/`. Тест = снапшот. Тогда AI может свободно рефакторить `exporters.js`: если снапшоты совпали — поведение не изменилось. **Это ключ к безопасной работе с AI над 38 КБ кода экспорта.**
2. **Дайте агенту карту репозитория** (`AGENTS.md` / `CLAUDE.md`): архитектура, соглашения, инварианты симуляции, команды `npm test`. Без этого агент будет ломать семантику routing.
3. **Генерация экспортеров — самая выгодная задача для AI.** У вас уже есть рабочий Java-экспорт (образец). Попросите агента по нему сгенерировать TS/Python/Go по спецификации формата. Один промпт → 300 строк кода, которые вы только ревьюите.
4. **AI для контента маркетинга** (см. §7) — статьи, README, changelog, скрипты видео, перевод справки.
5. **AI-ревью документации** — проверка, что README не врёт про возможности.

**Инфраструктура для агента:** `AGENTS.md` в корне + `npm run test` как единая команда проверки + `npm run build` для проверки сборки.

### 5.2 Слой 2: AI внутри продукта (фичи)

**Ограничение, определяющее всю архитектуру:** продукт офлайн → AI не должен его ломать. Решение — **BYOK (Bring Your Own Key)**: пользователь вставляет свой API-ключ, запрос уходит из его браузера напрямую к провайдеру. Ноль расходов автора, ноль хранения данных у вас, работа в закрытом контуре.

**Провайдеры (приоритет для РФ):**

| Провайдер | API | Почему |
|---|---|---|
| **GigaChat** (Сбер) | OpenAI-совместимый | Бесплатные лимиты для разработки, данные в РФ → нет вопросов с 152-ФЗ, сильны на русском |
| **YandexGPT** (Yandex Cloud) | OpenAI-совместимый | Дешёвые тарифы, есть free-tier/пробный период, сильны на русском |
| **OpenRouter** | OpenAI-совместимый | Для международной аудитории, агрегатор моделей |
| **Локальный Ollama / LM Studio** | `http://localhost:11434/v1` | **Ключевое для enterprise**: полностью air-gapped, данные не покидают машину |
| **OpenAI / Anthropic** | Прямые | Для intl-пользователей |

Единый адаптер: всё что говорит `/v1/chat/completions` — работает одинаково. Один провайдер подключается за 15 минут.

**Приоритет AI-фич (по ROI):**

| # | Фича | Что делает | Ценность | Сложность |
|---|---|---|---|---|
| **A1** | **Текст → топология** | Описание архитектуры на русском/английском → готовый холст | **Максимальная.** Архитектор описывает 5 сервисов → получает схему + экспорт | Средняя |
| **A2** | **Lint топологии** (правила + AI-объяснение) | Находит: нет DLQ, classic-очередь вместо quorum, нет TTL на retry, exchange без биндингов, topic-exchange с `*` в direct, отсутствие alt-exchange, нет publisher confirms | Высокая. Правила детерминированные (бесплатно, точно), AI только формулирует текст | Низкая |
| **A3** | **Объяснение топологии** | Импорт чужого `definitions.json` → человекочитаемое описание: что публикует, кто потребляет, где dead-letter | Высокая. Это то, что нужно при code review и при разборе инцидента | Низкая |
| **A4** | **«Спроси холст»** | «Почему `order.created` попал в `orders.dlq`?» → объяснение маршрута | Средняя-высокая | Средняя |
| **A5** | **Генерация документации/ADR** | Из топологии → Markdown для Confluence + ADR + диаграмма Mermaid | Средняя (у вас уже есть Markdown-экспорт, AI его улучшает) | Низкая |

**Реализация A1 (эталон, как делать):**

```
1. textarea → «Опишите архитектуру»
2. POST {baseUrl}/v1/chat/completions
   system: «Ты архитектор RabbitMQ. Верни ТОЛЬКО JSON по схеме:
            {nodes:[{id,kind:producer|exchange|queue|consumer,name,exchangeType?,routingKey?}],
             bindings:[{from,to,routingKey?}]}.
            Ничего не комментируй.»
   response_format: { type: 'json_object' }   // если провайдер поддерживает
3. Валидация JSON-схемой (ajv — 1 зависимость, ~120 КБ, или свой валидатор на 40 строк)
4. Показать ПРЕВЬЮ во временном слое, кнопки «Применить» / «Отменить»
5. Никогда не применяем результат молча — только по подтверждению пользователя
```

**Правила безопасности AI-фичи (важно для enterprise-продаж):**
- Ключ хранится в `localStorage`, шифруется через WebCrypto; никогда не отправляется на ваш сервер (у вас его нет — это и есть плюс).
- В UI явная строка: «Данные отправляются в <провайдер>. Ваш API-ключ не покидает браузер».
- Режим «Полностью локально» (Ollama) — для закрытого контура.
- Кнопка «Объяснить без AI» — весь core работает без единого сетевого запроса.

**Стоимость AI-слоя для автора: 0 ₽** (BYOK). Если захотите «из коробки» для новичков — отдельный бэкенд на Yandex Cloud Functions + GigaChat (данные в РФ), ~1000–3000 ₽/мес при небольшом объёме.

## 7. Маркетинг и продвижение

### 7.1 Позиционирование (одним предложением)

> **RabbitMQ Designer** — визуальный проектировщик топологии RabbitMQ, который работает офлайн в одном HTML-файле и сразу отдаёт `definitions.json`, код интеграции и документ для нормоконтроля. Без сервера, без аккаунта, без телеметрии.

Подзаголовок для сайта: *«Схема → конфиг → код → документ. Один файл. Работает в закрытом контуре.»*

### 7.2 Почему это продаётся именно в РФ

1. **Закрытый контур и 152-ФЗ** — SaaS-инструмент, который отправляет схемы в облако, юристу невозможно согласовать. Локальный инструмент — согласование на одну страницу.
2. **Нормоконтроль** — в российских компаниях архитектура MQ описывается в документах и проверяется. Ваш Markdown-экспорт — это ровно то, что требуется. Это **не** фича для галочки, а снимание бюрократического барьера.
3. **Свой стек генерации кода под Spring AMQP** — доминирующий стек в RU-enterprise.
4. **Нет конкурента с этим набором.** tryrabbitmq.com — симпатичный симулятор без экспорта в код. RabbitGUI/Ticketman — живые инспекторы, нужна сеть.
5. **Импортозамещение как модель** — «свой open-source инструмент вместо зарубежного» — рабочая риторика для платёжеспособного enterprise-клиента.
