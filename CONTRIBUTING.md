# Как участвовать в разработке

Спасибо, что заглянули. Проект небольшой и намеренно простой — это не случайность, а требование
к продукту. Ниже — правила, которые нельзя нарушать, и то, как всё устроено.

## Запуск

Никакой сборки, никаких зависимостей:

```bash
# просто открыть файл в браузере
start index.html          # Windows
open index.html           # macOS
xdg-open index.html       # Linux

# либо локальным сервером, если удобнее
python -m http.server 8000
npx serve .
```

## Тесты

Тесты запускаются в Node без установки пакетов — они читают файлы через `eval` в
поддельный `window`:

```bash
node test-logic.js   # логика маршрутизации, симуляция, dead-letter, импорт/экспорт
node test-rk.js      # unit + e2e: routing keys, таблицы ожиданий
```

Оба скрипта печатают итог вида `unit N/N, e2e N/N` и `ok=…, errors=…`.
**Перед PR оба должны быть не хуже, чем до ваших изменений** — сравните с базовой линией
на `main`.

## Что нельзя нарушать

Это инварианты продукта. PR, который их ломает, не будет принят, даже если код хороший.

1. **Нет бэкенда.** Приложение не должно требовать сервера, аккаунта или базы данных.
2. **Нет сетевых запросов с данными пользователя.** Топология не покидает машину.
3. **Работает с `file://`.** Двойной клик по `index.html` — основной сценарий запуска.
   Никаких `fetch` к локальным файлам, ES-модулей и прочего, что ломается на `file://`.
4. **Нет шага сборки на текущем этапе.** Файлы подключаются тегами `<script>` в `index.html`.
   (esbuild-сборка в один файл появится позже и не отменит пункт 3.)
5. **Ванильный JS.** Без React/Vue/Svelte и без транспиляции. Код должен исполняться
   в браузере как есть.

## Структура

```
index.html        — каркас, порядок подключения скриптов
style.css         — тёмная тема
i18n.js           — строки RU + EN (window.I18N)
presets.js        — пресеты: myproject, fan-out, blank (window.PRESETS)
core.js           — движок: модель, routing, симуляция, dead-letter (без DOM)
exporters.js      — definitions.json / Spring AMQP Java / Markdown
help-content.js   — текст справки
storage.js        — автосохранение, проекты, защита от потери данных
render.js         — SVG-холст, инспектор, тосты, RAF-цикл
test-logic.js     — тесты логики
test-rk.js        — тесты routing key (unit + e2e)
```

Модули — это IIFE, которые регистрируют себя на `window`:

```js
(function () {
  var RMQ = window.RMQ = window.RMQ || {};
  // ...
})();
```

`core.js` **не должен** обращаться к DOM: это позволяет тестировать движок в Node.

## Стиль кода

- **ES5-совместимый синтаксис**: `var`, `function`, стрелки и `let`/`const` не используются.
  Причина — запуск «как есть» в старых корпоративных браузерах без сборки.
- Отступ — 2 пробела, точка с запятой обязательна.
- Приватные функции — внутри IIFE, наружу — только то, что реально нужно (через `RMQ.*`).
- Комментарии — по-русски, по делу. Не описывайте очевидное, объясняйте **почему**.
- Одному изменению — один смысл.

## Локализация

Любая новая строка интерфейса добавляется **двумя** ключами в `i18n.js` — `ru` и `en`.
PR с одной локализацией не принимается: половина интерфейса на другом языке выглядит как баг.

Проверка: переключите язык кнопкой в шапке и пройдите по затронутому экрану.

## Экспорт

Если меняете `exporters.js`, проверьте результат вживую:

- `definitions.json` должен импортироваться в RabbitMQ
  (`rabbitmqctl import_definitions definitions.json`);
- сгенерированный Java должен компилироваться в типовом Spring Boot + Spring AMQP проекте.

Если меняется формат вывода — обновите `test-rk.js`, там есть проверки экспорта.

## Коммиты и PR

- Сообщения — [Conventional Commits](https://www.conventionalcommits.org/ru/):
  `feat: …`, `fix: …`, `docs: …`, `test: …`, `refactor: …`, `chore: …`.
- В описании PR укажите: что изменилось, зачем, как проверяли (команды и результат).
- Приложите скриншот, если менялся интерфейс.
- Один PR — одна задача.

## Что приветствуется

- Исправления маршрутизации и симуляции с тестом, воспроизводящим баг.
- Новые экспортёры (Terraform, docker-compose, mermaid, draw.io, код на TS/Python/Go).
- Улучшения доступности и клавиатурной навигации.
- Переводы и вычитка текстов.
- Замена CDN-JSZip на нативный ZIP-writer.

## Что не приветствуется

- Перевод проекта на фреймворк.
- Добавление бэкенда, аналитики, «облака».
- Сборка, требующая `node_modules` для запуска приложения.
- Массовые переименования и переформатирование «заодно».
