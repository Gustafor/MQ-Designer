# Политика безопасности

## Модель угроз

RabbitMQ Designer — **полностью клиентское** приложение. У него нет бэкенда, нет учётных записей
и нет телеметрии: данные пользователя не покидают его машину.

- Вся работа хранится в `localStorage` браузера и в файлах `.rmq.json`, которые пользователь
  выгружает сам.
- Из внешних ресурсов загружается **только** JSZip 3.10.1 с `cdnjs.cloudflare.com`
  (асинхронно, с обработкой `onerror`; без него приложение работает, теряется только ZIP-экспорт).
  Замена на нативный `CompressionStream` запланирована.
- Приложение не отправляет сетевых запросов и не собирает статистику.

Из этого следует: классические серверные уязвимости (SQL-инъекции, SSRF, утечки БД) здесь
неприменимы. Значимые риски — на стороне браузера и импортируемых файлов.

## Что считается уязвимостью

Сообщайте, если нашли:

- **XSS / HTML-инъекцию** через импортируемый `.rmq.json` или `definitions.json`
  (имя узла, routing key, заголовки сообщений попадают в DOM).
- **Prototype pollution** или иную порчу состояния при разборе импортируемого JSON.
- **Выполнение произвольного кода** (`eval`, `new Function`, `innerHTML` с внешними данными).
- **Утечку данных наружу** — любой сетевой запрос, которого нет в списке выше.
- **Обход предупреждений о потере данных** (автосохранение, `beforeunload`, guard при замене схемы)
  с фактической потерей работы пользователя.
- **Отказ в обслуживании** через специально сформированный файл проекта
  (бесконечный цикл, исчерпание памяти).

## Что не считается уязвимостью

- Доступ к машине, на которой открыт файл, и вредоносные браузерные расширения.
- Компрометация `cdnjs.cloudflare.com` — известный риск, отслеживается отдельной задачей.
- Поведение самого браузера: общий `localStorage` для всех страниц `file://`,
  ограничения приватного режима, политики администратора.
- Отсутствие CSP-заголовков: приложение запускается с `file://`, где заголовки не ставятся.

## Как сообщить

**Не создавайте публичный issue.**

Используйте приватный канал GitHub:

1. Откройте вкладку **Security** в репозитории.
2. **Advisories** → **Report a vulnerability**.

Укажите:

- версию (хэш коммита или дату скачивания);
- браузер и ОС;
- шаги воспроизведения и, если есть, файл `.rmq.json`, на котором воспроизводится проблема;
- оценку последствий.

## Что будет дальше

- Подтверждение получения — в течение 7 дней.
- Оценка и план исправления — в течение 30 дней.
- Публичное раскрытие — после выхода исправления, по согласованию с автором.
- В кредитах релиза укажем ваше имя, если вы не против.

## Поддерживаемые версии

Исправления выходят только для текущей ветки `main`. Отдельных LTS-веток нет:
приложение распространяется одним HTML-файлом, обновление — повторное скачивание.
